How it works

Your pipeline stays yours. TunaRAG owns the experiment around it.

Your application keeps retrieval, generation, indexes, provider clients and credentials. TunaRAG schedules trials, isolates failures, persists every result, and hands back a ranking you can inspect.

01 / CONNECT

Wrap your existing pipeline

Use LangChainAdapter, LangGraphAdapter or GoogleADKAdapter with a factory that builds your pipeline for each candidate configuration.

02 / DEFINE

Describe what to search and how to score

Declare a SearchSpace, pick evaluators (custom metrics or RAGAS), and combine them into a weighted Objective across quality, cost and latency.

03 / OPTIMIZE

Run, resume and inspect

Optimizer.optimize() runs the study with retries, caching and stop rules, then returns ranked trials you can export to JSON or CSV.

Features

Structured, repeatable studies instead of eyeballing a few answers.

Every trial is recorded, every failure is isolated, and every run can be reproduced. Tune top_k, chunking, prompts, models, reranking or generation settings.

Objective

Quality, cost and latency in one score

Weight answer quality against provider cost and response time. Cost reports say whether they are exact, estimated or unavailable.

Search

Random or LLM-guided

Deterministic RandomSearch with a seed, or provider-neutral LLMSearch that proposes the next candidate from past observations.

Evaluation

Your metrics or RAGAS

Write a MetricEvaluator in a line of Python, or plug in RagasEvaluator with RAGAS metrics such as faithfulness and answer relevancy.

Persistence

SQLite records and resume

SQLiteStore records every trial. An interrupted study picks up where it stopped instead of paying for the same calls twice.

Runtime

Caching, retries and budgets

Retry policies, concurrency, a SQLiteCache, and stop rules such as MaxTrials, CostBudget, TimeBudget and NoImprovement.

Data

Bring a dataset or synthesize one

Load records into EvaluationDataset, or build question-and-answer pairs from your documents with SyntheticDatasetBuilder. Held-out splits keep tuning honest.

Quickstart

A study in a few lines.

Point an adapter at your chain, describe the space, choose a score. The full offline example runs without API keys.

  • Typed public API, imported as tunarag
  • No paid provider calls unless you make them
  • Deterministic, redacted reports
  • Callbacks for MLflow and your own tooling
Full quickstart
tune.py
from tunarag import (
    IntegerRange, LangChainAdapter, MetricEvaluator,
    Objective, ObjectiveTerm, Optimizer, RandomSearch, SearchSpace,
)

optimizer = Optimizer(
    adapter=LangChainAdapter(
        factory=build_chain,  # your chain, built per candidate
        input_mapper=lambda example, candidate: example.query,
        identity={"app": "my-rag", "revision": 1},
    ),
    strategy=RandomSearch(
        SearchSpace({"top_k": IntegerRange(1, 8)}), seed=7
    ),
    evaluators=(MetricEvaluator("retrieval_recall", recall),),
    objective=Objective((ObjectiveTerm("retrieval_recall"),)),
)
try:
    result = optimizer.optimize(dataset, study_name="my-rag")
    print(result.best_candidate.parameters)
    result.write_csv("artifacts/trials.csv")
finally:
    optimizer.close()

Install

Lightweight core, optional extras.

The wheel ships runtime code only. Framework dependencies load lazily, so install the extra for your pipeline before you construct its adapter.
